# 卡萨帝二联供空调 协议规格笔记

用途: `src/brands/` 卡萨帝品牌模块实现依据
数据来源: 桌面 4 组抓码目录(2026-08-21 抓取, 16 场景) + 3 轮解码产物交叉验证
置信度标注: [实测]=抓码验证 / [推算]=规律推断, 上机前需确认

## 1. 传输层 (串口字节 ≠ 协议字节)

原始串口字节是 **2:1 位展开编码**: 每个协议字节拆成 2 个串口字节传输,
标记位 0x55 恒为 1。

```c
/* 解码: 输入字节对 (b0, b1) → 协议字节 */
if ((b0 & 0x55) == 0x55 && (b1 & 0x55) == 0x55)
    out = (b0 & 0xAA) | ((b1 & 0xAA) >> 1);
else
    ; /* 同步错误, 丢字节 */
```

抓码文件每行 = UART 中断切片, **行边界 ≠ 帧边界**, 必须解码后拼流再定帧。
→ gateway 落地: `decoder_t` 子类(卡萨帝位展开解码器), 输出协议字节给 receiver。

## 2. 帧结构 [实测]

总线上是"一问一答两包连发": 查询包(AB AB) + 应答包(AF AF) 背靠背。
抓码工具是总线监听, 两个方向都录到, 但每行只标"收←◆"。

### 包1 查询头 (14B 固定)

```
AB AB | 03 81 | 指令 2B | 包长 1B | 功能码 1B | 起始寄存器 2B | 数量 2B | CRC16 2B
```
* **包长 1B = 整包字节数(含包头、包长自身、CRC)**: 查询 0x0E=14,
  写单/双/四寄存器 0x11/0x13/0x17 = 17/19/23 字节, 6/6 帧字节计数验证
* 功能码: 03 = FC03 读保持寄存器, 10 = FC10 写多寄存器(标准 Modbus FC)
* 指令 2B (03 01 / FF FF / FF 01 / FF 00): 语义未知, 仅区分轮询轮次
* CRC16: 标准 MODBUS 算法(poly 0xA001 反射, init 0xFFFF, 小端), 覆盖包头到负载末尾,
  8 种查询帧 + 4 种写命令自算全部命中(12/12)

### Modbus RTU 血统 (2026-08-28 确认)

本协议是 **Modbus RTU 的变体封装**:

| 卡萨帝字段 | Modbus RTU 对应 |
|-----------|----------------|
| 03 81 | 未知段前 2B(疑似站地址: 03=面板, 81=内机, 待确认) |
| 包长 1B | 私有成帧(无 Modbus 对应): 整包字节数, 0x0E/0x11/0x13/0x17 = 14/17/19/23B, 13 帧验证 |
| 功能码 1B | 标准 Modbus FC: 03=读保持寄存器, 10=写多寄存器 |
| 对象ID 2B | 寄存器起始地址(FC03 读 / FC10 写, 同一张表) |
| 长度/数量 2B | 寄存器数量(查询数量与应答数据量吻合, 8/8 命中) |
| 数量2B+字节数1B+数据 (写帧) | FC10 标准结构, 4 种写命令 CRC 自算 4/4 命中 |
| CRC16 | 标准 MODBUS CRC16 |

**寄存器地图** (查询起始地址与写命令地址同一张表):

| 地址段 | 数量 | 内容 |
|--------|------|------|
| 0x0000 | 10 | 基本状态 |
| 0x000A | 22 | 运行状态: **0x000A=电源**(值 0x2C44 关/0x2C45 开, bit0), **0x0011=模式**, **0x0012=设定温度**(×10), **0x0013=风速**, 0x001D/0x001E=时间 |
| 0x0064 | 35 | 状态E(未知) |
| 0x012C | 15 | 温度区 |
| 0x0190 | 31 | 状态D(未知) |
| 0x2328 | 38 | 状态F(多传感器) |
| 0x2710 | 25 | 状态C(未知) |

→ 控制命令 = FC10 写对应寄存器, 格式已确认(见第 6 节缺口更新)。

### 包2 应答 (变长)

```
AF AF | 03 01 03 01 | 包长 1B | 功能码 1B | 起始寄存器 2B | 数据... | CRC16 2B
```
* 包长 1B = AF AF 包整长 = 整帧长 - 14, 7 种应答全部命中(21/2B/39/3F/4B/53/59)
* 功能码 03 + 起始寄存器 = 请求回显 (FC03 应答语义)
* 数据区 = 1B 前缀(0x2C) + 数量×2B 寄存器值, 7/7 命中 (包长 - 12 = 1 + 数量×2)
* CRC16: MODBUS, 覆盖 AF AF 起到数据末尾
* 定帧建议: 包长字段 + 超时封包双保险

### 整帧长度速查 (AB AB 头 + AF AF 包)

| 对象ID | 含义 | 整帧长 | 包2 payload | 轮询位次 |
|--------|------|--------|-------------|----------|
| 00 00 | 基本查询 | 47B | 29B | 第7、8位(FF FF / FF 01) |
| 01 2C | 温度状态 | 57B | 39B | 第2位 |
| 00 0A | 模式/风速/电源 | 71B | 53B | 第3位 |

## 3. 字段定义 (整帧偏移, 含 AB AB 头 14B) [实测]

### 71B 帧 (对象 00 0A) — 控制/状态主帧

| 偏移 | 字段 | 取值 |
|------|------|------|
| 24-25 | 电源 | 2C 44=关, 2C 45=开 (实际变化位=偏25) |
| 40 | 模式 | 00智能 01制冷 02除湿 04制热 05送风 06地暖 07地暖强热 |
| 42 | 温度关联值 | F0=24.0°C, FA=25.0°C (×10, 0.5°C 步进=差5) |
| 44 | 风速 | 00自动 07=1档 06=2档 05=3档 04=4档 03=5档 02=6档 01=7档 |
| 46 | 模式子参数 | 随模式联动 (0A/02/00), 待定 |
| 29/64/66 | 传感器/计时波动 | 非控制量 |

验证: 9 个场景文件的模式值集合与文件名逐一对应
(智能切制冷 {00,01}, 制冷切除湿 {01,02}, 除湿切制热 {02,04},
制热切地暖 {04,06}, 地暖强热切送风 {05,07});
风速 7 组切换 07→06→05→04→03→02→01、自动 00 全部命中;
开关机 45↔44 命中。

### 57B 帧 (对象 01 2C) — 温度帧

| 偏移 | 字段 | 换算 |
|------|------|------|
| 42 | 设定温度 | (值-32)/4 °C; 0x84=25.0°C, 0x98=30.0°C; 0.5°C 步进=值差2 |
| 44 | 室温 | (值-32)/4 °C, 抓码范围 0x76~0x7E = 21.5~23.5°C |

注意: 读帧换算 (x-32)/4 与写命令换算 x/10(0xA5=16.5°C) **方向不同**, 勿混用。
偏38/42/50 的 31/36/3B、96/9C 交替为传感器类波动, 待实机标定。

## 4. 轮询时序 [实测]

* 帧间隔 230~250ms, 8 查询一轮 ≈1.7~1.9s, 顺序见上表轮询位次
* 上电初始化: 连发 11 次基本查询(FF FF, 间隔≈226ms) → 1 次 FF 01 → 进入稳态轮询
* 全部 16 文件数千帧中 8 种查询帧内容**零变化** → 纯周期轮询, 无写命令
* 模式/温度/风速切换由遥控器(红外)直接操作内机, 线上只体现为应答数据变化

## 5. 与 gateway 框架的映射 (实现建议)

| 协议需求 | 框架落点 |
|----------|----------|
| 0x55 位展开解码 | `decoder_t` 子类 (casartte_bit_decoder), HAL 已留 `feed_byte/feed_sample` 扩展点 |
| 14B/变长两包分帧 | `receiver_timeout_t` 现有 5ms 超时即可——两包之间线上间隔若 >5ms 会自然切成 AB AB / AF AF 两帧, 品牌层再按对象ID配对; **两包实际间隔需实机测**(若 <5ms 会粘成单帧, 依赖 len 字段二次切分) |
| CRC16/MODBUS 校验 | 品牌层 on_rx_frame 内做, 丢 CRC 错帧 |
| ~230ms 轮询 | module poll_timer 默认 200ms, 接近; 品牌层按 8 帧序列轮转发查询 |
| 丢帧计数 | 全链路已有, 抓码覆盖率 96~99% 说明线上本身有丢帧, 计数是常态指标 |

## 6. 已知缺口 (实现前必须解决)

1. **写命令格式已确认** (2026-08-28 更新): FC10 写多寄存器 + 包长字段结构,
   原先存疑的"功能码前缀 0E/11/13/17"实为**包长**(整包字节数), 字节计数 6/6 吻合,
   CRC 4/4 命中。剩余待确认: 03 81 未知段、应答数据区 2C 前缀与寄存器逐字节对齐。
   实机先监听原厂面板写操作印证, 再试发。
2. AB AB 与 AF AF 两包的线上间隔未测 (影响 T4 定帧策略)。
3. 状态C/D/E/F (0x2710 / 0x0190 / 0x0064 / 0x2328) 四段寄存器字段未解析 ——
   不影响基础控制, 查询轮次保留即可。
4. 71B 帧偏42 的温度换算(×10)仅 2 个样本, 需结合温度连续控制文件复核
   (57B 帧偏42 的 (x-32)/4 已多样本确认)。
5. 应答帧数据区与寄存器地址的逐字节对齐关系未钉死(0x000A 寄存器值=2C 44/45 已对上,
   模式/风速在数据区的奇偶偏移差 2 字节, 疑似数据区前有 2B 前缀, 实机验证)。
